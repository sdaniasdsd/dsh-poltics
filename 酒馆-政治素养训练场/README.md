# 酒馆 · 政治素养训练场

> 一个给 SillyTavern（酒馆）内部用的训练素材工程。
> 目标：让用户在**真实发生过的职场冲突**里做选择，然后用一套以「利益」为唯一标尺的评分体系结算。

---

## 一句话说清这个项目在做什么

市面上的职场内容要么是鸡汤（"要高情商"），要么是爽文（"当场怼回去"）。
这个项目赌一个相反的判断：

> **政治素养的高低，最后只看一件事——你有没有为自己、或者为你身边的人，把利益真正拿到手。**

所以整个训练场围绕两条线搭：

1. **素材线**：从知乎、抖音（经工劳短视频平台转录）、公开判决等渠道，收集销售 / 工程师 / 采购 / 工人四个岗位的**真实人际冲突经历**，筛出有戏剧性、有具体人物、有可判断结局的那些。
2. **评分线**：一套把"利益"拆成可计量项目、把"代价"和"风险敞口"扣干净的评分标准。

## 评分标准速览

完整版见 [`02_评分标准/利益获取评分标准_v1.md`](02_评分标准/利益获取评分标准_v1.md)，算账样例见 [`02_评分标准/评分算例.md`](02_评分标准/评分算例.md)。核心就四句话：

1. **只算利益，不算姿态。** 说得漂亮、赢了辩论、让对方下不来台、拿到道德高地，全部记 0 分（R1）。
2. **算净额。** `主分 = 自己净额 + 0.8 × 他人净额`，其中净额要扣掉时间、关系、机会成本，以及**遗留的风险敞口**。
3. **重大合规敞口一票降级**（R3，最终等级最高 C）。所以"埋雷报复""当众撕破脸""碾车讨薪"这类爽文结局，在本标准下全部是负分。
4. **两条例外条款**（v1.1，试算 68 张真实素材后补的）：
   - **R11 局面边界**——跳槽/副业带来的好处不算进"我赢了这场斗争"；
   - **R12 他人轴只计自然人**——"公司少亏了钱""部门拿回主导权"不算你帮别人争取到了利益。

等级：`S`（把局做大了）→ `A`（赢了且落袋）→ `B`（小胜有暗伤）→ `C`（没输）→ `D`（白忙）→ `E`（亏了）→ `F`（把自己搭进去）。

每张素材卡都带一个 **`proxy_score`**：真实故事里当事人自己的结算。用户打完一局可以跟它对表。

## 素材卡长什么样

每张卡（结构见 [`01_素材库/_卡片规范.md`](01_素材库/_卡片规范.md)）都包含训练场所需的全部要素：

- `scene` —— 用户 30 秒内能看懂的开场："你是谁、面前是谁、当下要做什么决定"
- `cast[].surface` / `cast[].hidden` —— 每个关键 NPC 的**表面诉求 vs 隐藏诉求**（这是训练场的命门）
- `info_asymmetry` —— 谁掌握了谁不知道的信息
- `escalation` —— 冲突升级的时间线
- `stakes` / `conflict_point` / `branches` —— 利益敞口、核心冲突、可做的选择分支
- `proxy_score` —— 原型的利益结算（含 `reason`，引用评分标准规则编号）
- `evidence` —— **逐字复制**的原文片段，用来证明卡片没有编造
- `fidelity` —— 诚实标注这条素材是「直接转述」还是「叙事性写作（可能有虚构）」

## 采集方法（可复现）

1. `web_search` 分岗位检索线索，收集候选 URL。
2. `tools/collect.ps1` 通过 Tabbit 浏览器（真实 Chromium）批量打开页面，抽取正文，落盘为 `raw/*.json`。
   - 命令示例：
     ```powershell
     & tools\collect.ps1 -UrlsFile tools\urls_sales.txt -RequestId sales01 `
       -Task harvest-sales -OutDir 01_素材库\raw -MaxAnswers 6 -MaxChars 6000 -Concurrency 3
     ```
3. `tools/triage.ps1` 生成 `_triage.md` 筛选视图。
4. 人工筛选 → 生成素材卡 → `tools/verify_cards.ps1` 自动校验，再做一次人工复核（记录在 `_人工复核修正记录.md`）。

### 渠道可用性（实测，重要）

| 渠道 | 能否直连 | 结论 |
|---|---|---|
| 知乎 | ✅ | 问答页与专栏都能抓。**但只渲染首屏 3~5 条回答**，要拿全量得先滚动触发懒加载 |
| B 站 | ✅ | 视频页正文能抓，出过硬素材；但搜索结果多为自媒体讲解，**真正有价值的是打工人 vlog** |
| 抖音 | ✅ | **登录墙只在 `/search/`**。`/video/`、`/shipin/`、`/note/` 详情页不需要登录，文案 + 评论区 + 相关视频都能读。发现环节改用 `web_search`（它能索引到抖音链接）。见 `tools/collect_douyin.ps1` |
| `web_fetch` 工具 | ❌ | 本机走 fake-IP 代理（DNS 解析到 198.18.x.x），该工具的安全检查会判定为非公网地址并拒绝。**必须走真实浏览器** |

> **免责与来源说明**：本目录下所有故事均为公开网络平台的**他人自述或转述**，不是本项目原创，也不代表事实已核实。每张卡的 `source.url` 指回原始出处，`fidelity` 标注了可信度层级。带 `有加工` / `疑似虚构` 标记的素材只可用于训练推演，不可当作事实引用。
> 素材中含灰色收入、回扣、报复等情节，是真实职场博弈的一部分；评分标准**不做道德说教，只做风险定价**。
> 做成酒馆资产时要替换掉可识别的真实姓名与公司名——**一旦用户认出具体是谁，训练场就变成八卦现场了**（详见 [`03_酒馆资产设计/`](03_酒馆资产设计/素材卡到酒馆资产的映射.md)）。

## 第三步：可玩剧情 + 前端（进行中）

第一步交付的是**研究层**（素材卡，带 evidence/fidelity，回答"现实里发生了什么"）。
第三步要交付的是**可玩层**：用户选一篇剧情、选一个主角，进去打一局，然后被结算。

```
01_素材库/cards/*.json        研究层：68 张素材卡（有原文引用，可核对）
        ↓  筛选 + 改写
04_剧情/scenarios/*.json      可玩层：20 篇剧情，每篇 2~3 个可扮演主角
        ↓  转换器
$DSH_HOME/dsh-tavern/         装进 dsh-liketavern 插件
        ↓  前端 UI
「选剧情 + 选主角」界面        在 DeepSeek Harness 里直接开玩
```

### 「选择扮演主角」为什么是关键设计

**同一篇剧情，可以扮演不同的人。** 起手信息、利益目标、可用筹码完全不同，最优解常常相反。

以 `E-10`（副总拿我的成果做投名状）为例：

| 可扮演 | 你要争的利益 | 起手就知道 | 起手不知道 | 难度 |
|---|---|---|---|---|
| 陈大懒（原型） | 软著署名 | 代码是你写的 | 副总已在给 A 工铺路 | 普通 |
| A 工（关系户） | 一个能立住的业绩 | 副总在帮你 | 这个项目你接不住 | 困难 |
| 副总 | 把功劳分给"自己人"且不留痕 | 董事长要 A 工出成绩 | 陈大懒已准备好走了 | 困难 |

用户在同一个局面里换位之后才会明白：**政治素养不是道德判断，而是位置决定筹码。**

### 内容放在哪

- **不放进插件仓库**。插件仓库遵守 `AGENTS.md`：真实数据只住 `$DSH_HOME/dsh-tavern/`，不进源码、测试、Git 或 npm 包。
- 剧情内容在本项目 `04_剧情/` 下编辑，由 `tools/build_cards.mjs` 安装进插件数据目录：
  ```powershell
  node tools/build_cards.mjs --dry   # 只校验
  node tools/build_cards.mjs         # 写入 $DSH_HOME/dsh-tavern/characters/
  ```

### 为什么不用新增接口

「选择扮演主角」的元数据写进 `card.extensions['tavern-gym']`，前端经既有的
`getCharacterDetail.extensions` 读取——**零新增 RPC**，host / remote / service / state / core 全部未改。
主角下标与插件既有的 `cardGreetingVariants` 严格对齐，所以「选主角」就是改 `binding.greetingIndex`，
不存在第二套状态。
