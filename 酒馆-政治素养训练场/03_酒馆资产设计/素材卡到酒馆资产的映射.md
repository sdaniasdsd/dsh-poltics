# 从素材卡到酒馆资产的映射

> 这份文档不属于第一步的交付，只是先把"素材卡 → 酒馆能用的东西"的对应关系钉死，
> 方便下一步直接开工，也方便确认这张卡的字段设计没有缺项。

## 字段对应

| 素材卡字段 | 变成酒馆里的什么 | 说明 |
|---|---|---|
| `scene` | **开局第一条消息** | 直接作为 `first_mes` 的骨架。必须让用户在 30 秒内知道"我是谁、对面是谁、现在要决定什么" |
| `setting` | 开局消息的第二段 / 世界书条目 | 背景信息，作为常驻 World Info |
| `cast[]` | **角色卡（NPC）** | 每个关键人物一张卡。`surface` 进 `description`（用户可见的部分），`hidden` 进世界书并设为**不触发不下发** |
| `cast[].hidden` | 世界书条目（蓝灯/常量可选） | **这是训练场成立的前提**：NPC 必须有用户看不见的诉求，否则用户只是在跟复读机对话 |
| `cast[].leverage` | 角色卡 `description` 的补充 | 告诉模型这个 NPC 手里有什么牌，决定它的强硬程度 |
| `stakes` | 世界书条目 | 让模型知道"什么算赢"，否则它会自行发挥 |
| `conflict_point` | 世界书条目（常驻） | 一句话锁死矛盾，防止对话跑偏成闲聊 |
| `escalation` | 世界书条目（按轮次触发） | 按时间线做"第 N 轮触发"的定时事件，保证局面会自己恶化 |
| `info_asymmetry` | 世界书条目 | 决定模型什么时候该"说漏嘴"、什么时候该隐瞒 |
| `branches` | 世界书条目 + 备选回复 | 也可以做成"开局的三个选项" |
| `outcome` + `proxy_score` | **裁判提示词的知识库** | 用户在局末要求结算时，模型需要知道"现实里这条路通向哪" |
| `lessons` | 复盘消息的素材 | 局末揭示，或用户主动问"我哪里做错了"时给 |
| `evidence` | 不用进酒馆 | 只用于本项目的可信度审计 |
| `fidelity` | 不用进酒馆 | 同上；但决定这张卡是否适合做成对外内容 |

## 一张卡 → 三个酒馆资产

```
素材卡 S-03
├── 剧本（Scenario）      : scene + setting + conflict_point
├── 角色卡 × N（NPC）     : cast（每个关键人物一张）
└── 世界书（Lorebook）    : setting / stakes / escalation / info_asymmetry / branches
                          + 隐藏条目：cast[].hidden、proxy_score.reason
```

## 裁判提示词需要的三样东西

1. **《利益获取评分标准_v1.md》** → 作为 system prompt 的一部分，要求模型在局末按"利益记账表"逐项填写。
2. **本卡的 `stakes` + `outcome`** → 让模型知道这一局的目标是什么、现实的走向是什么。
3. **强制输出格式** → 直接复用评分标准第 6 节的「评分卡模板」，要求模型填满，禁止只给一个笼统评价。

## 一个必须注意的坑

素材里的 NPC 往往是**真人**。做成角色卡时要：
- 去掉或改写可识别的真实姓名、公司名（`cast` 里已经用 A/B/口罩哥这类代称）；
- 保留行为逻辑和权力结构，不要保留身份线索。

这不是法律洁癖，是因为**一旦用户认出具体是谁，训练场就变成了八卦现场**，用户的注意力会从"我该怎么决策"转移到"这人后来怎么样了"。
