# 剧情（Scenario）数据结构规范 v1

> 这一层是**可玩内容**，与素材卡（研究层，带 evidence/fidelity）分开。
> 素材卡回答"现实里发生了什么"，剧情卡回答"你要扮演谁、面对什么、怎么结算"。
> 输出为插件中立的 JSON，之后再转换进 dsh-liketavern 的卡片/世界书格式。

## 硬性规则

1. **`protagonists` 至少 2 个，最多 3 个**，且必须包含原型里的当事人。
   其余主角从**同一局面的其他位置**里选（对手、上级、旁观者）。
   > 这是本批最重要的设计：同一件事，站在不同位置，最优解完全相反。用户换位之后才会明白"政治素养"不是道德判断，而是位置决定筹码。
2. **每个主角的 `opening` 必须是第一人称、直接进入场景**，且不能剧透 `cast[].hidden`。
3. **`difficulty` 要诚实**：筹码最少、信息最少、时间最紧的那个位置标 `地狱`；原型当事人标 `普通`；有背景或先手的标 `困难`（对用户而言反而更难，因为容易高估自己）。
4. **`baseline` 只给原型当事人精确值**（从素材卡 `proxy_score` 取）。其他主角的 baseline 按 `_评分算例.md` 的方法推演给出，并在 `note` 里写明是推演。
5. **`evidence` 必须逐字来自素材卡**，不得改写。写完用 pwsh 在素材卡 JSON 里做子串校验。
6. **不得编造**姓名、公司、数字。素材卡没写的写「未提及」。
7. **`cast[].hidden` 是命门**：每个关键 NPC 都必须有表面诉求与隐藏诉求的**落差**。没有落差的人物不要列进 `cast`。
8. 输出为合法 JSON 数组，UTF-8 无 BOM。文件名：`scenarios/<role>.json`。
